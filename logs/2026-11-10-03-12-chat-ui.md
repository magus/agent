# Chat UI

## Context

The user wants a better composer, compact tool calls, and left/right messages. Their screenshots
show the intended visual direction. They requested a plan and goal before implementation.

## Decisions

- Follow-up screenshot review found doubled composer text padding and excessive control insets.
  Match the reference with a 12px text inset, 8px bottom/right control inset, and 28px send button.

- Focus this milestone on chat UI. Keep GPUI and central execution.
- Put current-conversation model and effort controls in the composer. Keep creation defaults in settings.
- Collapse tools into single-line rows and remove repeated message role labels.
- Preserve selection, keyboard controls, device visibility, immediate sends, and stable layout.

## Changes

- Moved model and effort controls above the composer, aligned right. Added signal bars before
  the effort label. User requested immediate response feedback; show an animated Thinking row
  on send and during model work, while running tool rows provide tool feedback.

- Applied clean-copy to the composer. Routine success and stop messages are hidden. Removed the
  permanent status strip. Errors and pending-result recovery appear only when needed, above the
  composer without shifting it. Backend status remains available for execution and diagnostics.

- Added docs/plans/chat-ui/README.md with scope, a checklist, and acceptance checks.
- Linked the milestone from the agent-core plan.
- Added Composer, message_bubble, and ToolRow components. Model controls moved into the composer;
  messages use left/right alignment and all tool calls start collapsed.
- Added per-conversation model settings and captured model/effort for each running turn. Changing
  the next turn's settings does not mutate the active request or future-conversation defaults.
- Tool expansion uses service, conversation, and request IDs rather than entry indices.
- Signed and notarized build installed on both Macs. Bundle identity and permissions are unchanged.
