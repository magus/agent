# device-tools

## Context

Build explicit device pairing and direct remote tools without inference or an agent loop.
Verify the laptop and locked mini, including revocation and reconnecting to command results.

## Decisions

- Use rustls TLS with certificates pinned during explicit pairing. Keep private identity material
  in Keychain. Use Tailscale addresses for connectivity, not as authorization.
- Keep approval directional. Pairing requests cannot execute tools. Recheck authorization on each
  request. Defer inference and concurrent desktop coordination.
- Use the running app for local administration through a private Unix socket, so CLI calls do not
  need separate Keychain or desktop permissions.

## Changes

- Added the `devices` module with Keychain identity, TLS 1.3 transport, explicit directional approval,
  persisted peers, and revocation. Invitations pin the target certificate, expire after 10 minutes,
  and can be claimed by only one device identity. Invalid certificates are rejected before approval.
- Added a Devices window and `--device REQUEST.json` client. The private admin socket belongs to
  the running app. The client does not read Keychain credentials or depend on ChatGPT login.
- Shell and computer tools accept an explicit paired host. Requests are saved before execution;
  repeated IDs return existing results. Disconnecting the client does not stop accepted work.
- Added shell timeout and cancellation, bounded output, and screenshot transfer. Results persist
  across app restarts. An unfinished result becomes interrupted and is not automatically rerun.
- Documented direct calls in `docs/plans/agent-core/tools.md`. No inference or agent loop was added.

## Verification

- All 19 Rust tests and Clippy passed. Tests exercise real TLS connections, wrong identities,
  certificate pinning, invitation expiry/reuse, malformed certificates, directional authorization,
  revocation, duplicate requests, cancellation, and persisted results.
- Both Macs ran signed, notarized builds. Device identities survived the update. The mini rejected
  requests before approval and after revocation, including after an app restart.
- Explicitly paired both directions. The laptop ran tools on the mini, and the mini ran a shell
  command on the laptop. The Devices window successfully reported the mini's available tools.
- The locked mini calculated `9 × 221 = 1989` using coordinate clicks. Every successful desktop
  action returned `locked: true`. Calculator moved from `(302, 539)` to `(402, 349)` without resizing.
- An early drag overlapped the last Calculator click in the test script. The expected-window guard
  rejected that stale click. A fresh capture and click at the new position completed the calculation.
- Bulk paste inserted 2,000 Unicode lines in one request. The saved file was 100,000 bytes with SHA256
  `4dad21b89b8c56d30a8d27ca8fe42096f5c0ca2436cf881d34bb01ba010a31d9`, matching the source exactly.
  Clipboard restoration passed. Paste dispatch took 1.19 seconds, including the consumption wait.
- A delayed shell command finished after the client exited. A new client retrieved its result.
  Repeating the same request ID left the counter at one byte. The result survived target restart.
- Cancelling a live shell command terminated it before its final output. Revoked new tool calls
  were rejected. Both behaviors were also covered by automated tests.
- Action/result JSON and screenshot pairs are retained under
  `.scratch/2026-11-08-03-10-device-tools/`, with `index.md` listing the evidence.
- Final notarization was accepted and stapled. Both installed executables have SHA256

  After restarting both final builds, both approved directions connected, a saved result remained
