# Chat and desktop review fixes

## Context

Addressed the nine findings in the [commit review](2026-11-25-02-23-commit-review.md).
Checked both open UI questions on the native clients.

## Decisions

- Keep the Unix activity timestamp. A separate persistent sequence number records the order in
  which the service accepts new activity. Older records still sort by their saved timestamps.
- Test UI failures using the production SwiftUI views, a local bridge fixture, and a separate
  test app. No paired device or ChatGPT account is needed.

## Changes

1. The chat shows errors below the navigation split view, including during startup. The connection
   sheet shows a failed service selection in the sheet and stays open.
2. The chat passes the original Markdown to Words. CSS displays the newlines Words emits in prose.
   Indented code, quoted fences, and multiline code spans keep the parser's original contents.
3. Only a failed or stopped run saves an unfinished reply. An empty successful completion keeps
   the Ready status and the original transcript.
4. The chat snapshot checks desktop permissions only when the chat shows device chips, a service
   is selected, and the local Mac is among the targets. Desktop action dispatch still checks through
   a fresh helper.
5. The service updates conversation activity when it saves a new message. A retry that finds a
   saved receipt returns its acknowledgment before this update.
6. The catalog saves the activity sequence under the store lock. The newest conversation stays
   first when two timestamps match and after the service reloads the catalog.
7. LF and CRLF render as the same single prose line break. Explicit Markdown hard breaks also
   occupy one line break.
8. A failed helper launch doubles the retry delay from two seconds up to one minute. Only a
   helper that actually ran for more than 30 seconds resets the delay.
9. Removed the obsolete mini deployment request and corrected the corresponding status in the
   previous audit. The Nov 24 deployment evidence and the untested installer retry remain.

- Fixed horizontal scrolling in the Pierre Words JSON viewer. Its code block wrapper now lets
  the document scroll across the whole line.
- Mac Find passed. Closing the chat, invoking Find once, and typing placed the query in Search
  titles. The automated check also asserts that the original window has closed.

## Verification

- All 63 Rust tests passed. The service tests verify saved and displayed outcomes for successful
  empty, failed, and stopped responses. They check accepted retries through the send and list
  endpoints and reload records with identical timestamps and fixed IDs in reverse activity order.
  Permission tests count unexpected probes as failures and check dispatch after cached grants.
- All five Node renderer tests passed. The original renderer failed the exact-text test by adding
  two spaces to an indented code line. Native WebKit checks measured two displayed lines for LF,
  CRLF, and both Markdown hard-break forms. They also checked the rendered code text.
- The original Swift views failed both native error checks. The updated views exposed the startup
  error in chat and the offline-service error after the test pressed the service button.
- The JSON viewer initially clipped the final character on both platforms. With the fix, the
  character scrolled from x=8304 to x=857 in an 868-pixel Mac viewport and from x=10860 to x=186
  in a 370-pixel iPhone simulator viewport. These are CSS pixels inside the native web view.
- The Mac test verified the retry sequence 2, 4, 8, 16, 32, 60, 60 seconds without waiting on a
  timer. A short run kept the cap, and a 31-second run reset the next delay to two seconds.
- Rust formatting, Clippy with warnings denied, and Git whitespace checks passed. Native check
  commands are in [the Apple packaging guide](../packaging/apple/README.md#chat-regression-checks).
- Both full production clients linked against the rebuilt Rust bridge. The iOS Rust build
  reported two existing unused-code warnings for `title_from_message`, which only the service uses.
- The iPhone check ran on the iPhone 17 Pro simulator. The tests used local fixtures and did not
  exercise a live model request, a physical iPhone, or a central-service deployment.
