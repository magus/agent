# UI audit and desktop control fixes

## Context

Overnight, open-ended audit of the native Mac and iPhone clients aimed at a useful, clean, simple
agent UI, with every change verified in the running apps (computer use on the Mac app, the
simulator tool on iPhone). Noah also decided that computer use must work whether the Mac is locked
or unlocked; the locked-only guard was a misunderstanding. Work happens on branch `ui-audit`;
nothing is pushed. Scratch: `.scratch/2026-11-23-03-38-ui-audit/`.

Constraints: no System Settings or permission changes, no ChatGPT sign-in changes, no pairing
changes, no deleted conversations. The Mac mini is read-only (info, harmless shell, capture); its
Agent app and the central service it hosts are not rebuilt or restarted.

## Plan

- P1: unlocked desktop control; explain unavailable computer use to the model and UI; prevent
  orphaned `desktop_service` helpers.
- P2: audit every screen and state on Mac and iPhone; keep ranked findings below.
- P3: fix findings, highest value first, each verified with before/after screenshots.

## Decisions

- Desktop control runs locked or unlocked. Each result reports the real `locked` state instead of
  a hard-coded `true`, so the model knows whether a person may be at the Mac. The setup preview no
  longer requires an unlocked Mac either.
- The model instructions live in `src/agent/service/chat/instructions.txt`, which the central
  service on the mini reads. They are updated in the repo but stay old on the mini until Noah
  deploys there.

## Changes

- `src/desktop_service/swift/desktop_control.swift`: removed `require_locked` and `require_unlocked`;
  added `screen_is_locked` for reporting.
- Updated `README.md`, `src/desktop_service/README.md`, `docs/plans/desktop-permissions/README.md`,
  and `instructions.txt` to describe locked-or-unlocked operation.
- Unavailable computer use now explains itself. `computer_permissions::check` names each missing
  permission and the fix (Agent → Desktop permissions…, or the System Settings pane, then reopen
  Agent). Device `info` carries `unavailable_tools` next to `tool_list`, and the agent loop passes it
  to the model. A failed dispatch returns the same reason. An unreachable helper says the desktop
  service is not running and to open Agent.app.
- Mac UI: the local device's chip shows a warning symbol with the reason as tooltip and accessibility
  hint. When that device is enabled for the conversation, a banner under the chips shows the reason
  with a **Desktop permissions…** button. The snapshot gained `local_device_id` and
  `local_unavailable_tools`.
- Orphaned helpers are prevented. With `--serve`, the helper watches its parent process and exits
  when the app exits (`service_main.swift`). On launch, the app stops helpers at its own bundle path
  whose parent is launchd, and it backs off restarts from 2 s to 60 s while the helper keeps failing
  at once (`DesktopService.swift`). The original orphan had kept the socket for about two days and
  filled `service.log` with 2.7 MB of "already running" errors.
- Navigation and discoverability (`ChatView.swift`, `ChatModel.swift`, `AgentCommands.swift`):
  - iPhone: the conversation list now has Settings and New conversation buttons; before, both
    existed only inside an open conversation.
  - Mac menu bar: File → New Conversation (⌘N) replaces New Window, which only mirrored the same
    chat. The Agent menu has Conversation Settings… (⌘,), Devices…, ChatGPT Account…, Connect to
    Service…, and Desktop Permissions….
  - Sheets are driven by one `ChatModel.sheet` value, so the toolbar, menu bar, and launch arguments
    open the same sheets.
  - The globe "Service" menu is now a gear "Settings" menu with the services in a section and a
    checkmark on the connected one. Accessibility labels read "Settings" and "Conversation actions"
    instead of the icon names "network" and "More".
  - A new or empty conversation shows "New conversation" and which devices Agent can run commands
    on, instead of a blank pane; creating shows a progress indicator and disables New conversation.
  - Docs use the new menu names.
- ChatGPT sheet: signed in, it shows "Signed in as <account>", Check connection, Sign in with
  another account, and Sign out; signed out, it explains the shared account and offers Continue with
  ChatGPT.
- Devices sheet: one options icon per row instead of "••• Connection"; access reads "This device
  can use it" / "It can use this device" instead of Outgoing / Incoming; a device with no access says
  so; the name field sits under "This device". Menu actions renamed to match, and
  `src/agent/devices/README.md` now describes the actual sheet (it referenced controls that don't
  exist).
- Conversation order and titles (central service): records carry `last_activity` (creation or the
  latest user message, Unix seconds) and the list is sorted by it, most recent first; records from
  before this change sort last. A conversation still named with the default "Conversation <id>"
  title takes its title from the first line of its first message, cut near 60 characters at a word.
  Retried creates match on creator only, since the title may have changed. The default title comes
  from one shared `protocol::default_title`.
- Tool rows: an expanded computer action shows one line ("Screenshot 3600 × 2338 · Mac was
  unlocked", or the error) and the screenshot instead of hundreds of lines of raw result JSON; the
  full result stays in View conversation JSON. Rows are neutral grey on iPhone instead of accent blue.
- Loading and empty states: while the client starts, the transcript shows a spinner and the model
  pickers stay hidden until a model is known (before: a blank pane and a picker with no name, then
  briefly the first model in the list). With no service connected, the pane explains what the service
  is and offers Connect to service….
- Markdown line breaks: single newlines in agent replies now render as line breaks outside fenced
  code (`assets/markdown/lineBreaks.js`), so "one number per line" no longer collapses into one
  line. Lists, tables, headings, quotes, and code render as before.
- Stopping: a reply stopped mid-stream used to vanish, leaving only the prompt with no sign it was
  stopped. The service now keeps unfinished streamed text as an entry marked "Stopped before
  finishing." (or "Interrupted…" after a failure); it is shown but not sent to the model. The client
  shows "Stopped." instead of hiding that status. "Thinking" no longer shows under text that is
  already streaming.
- Context: an open conversation shows its title (inline on iPhone, in the Window menu on the Mac),
  and enabled device chips carry a checkmark so their state is not shown by contrast alone. README
  wording about full contrast vs gray still holds.
- `TODO.md`: replaced the orphan item with the remaining bundle-ID decision; removed the resolved
  lock items.
- `.gitignore`: ignore `.claude/settings.local.json`.

## Verification

  MacBook, a chat-driven shell call succeeded and capture failed with
  "Expected locked graphical session".
- After rebuilding `dist/Agent.app`: a direct `--send` capture on the unlocked MacBook returned a
  3600-pixel-wide image with `locked: false`. Through a chat, the model captured the unlocked MacBook and
  reported "locked state: false (unlocked)". The mini's locked capture still succeeds.
- Quitting Agent from its menu stopped both processes; relaunch started one helper as its child.
- `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test` (55 passed).
- Unavailable-reason UI: a throwaway build with a forced reason showed the chip warning and banner
  (`p1-computer-unavailable-banner-forced.jpg`); its button opened Desktop permissions, and
  **Check capture** succeeded while unlocked. The real build shows no banner while permissions are

  permissions must not be changed. `cargo test` 56 passed, including a new wording test; the iPhone
  simulator build compiles and runs.

- Orphan handling: started an old-build helper detached (parent launchd), installed the new build,
  and launched it; the orphan was stopped and the app's own helper served a capture. Force-killing
  the app made its helper exit at once; the next launch removed the stale socket file and served a
  capture, with no new errors in `service.log`.

- Navigation: the Mac Agent and File menus list the new commands; Conversation Settings… opened from

- Ordering and titles: unit tests cover sorting (including old records without a time), title

- Tool rows and loading on the iPhone simulator: `ios-tool-row-before.png` → `ios-tool-row-after.png`,

## Findings

Ranked; fixed items move to Changes.

1. Fixed: a new conversation looked like nothing happened. Creation takes about a second over the
   network and then showed a blank pane; it now shows progress and an empty state.
2. By design: new conversations use the model and devices from Conversation settings, which are
   gpt-6.1-sol / Low here. Not changed.
3. Fixed in the service, pending deploy: conversations are titled "Conversation <hash>" when
   untitled.
4. Fixed in the service, pending deploy: the sidebar is ordered by conversation ID, which is
   random, so a new conversation lands mid-list.
5. The device list in chat comes from the central service, so a remote device's unavailable reason
   only reaches the UI after the service is extended and redeployed; the model already gets it.
6. After reinstalling the simulator build, the home-screen icon showed a blank placeholder even
   though the bundle includes icon files and `CFBundleIcons`; likely SpringBoard's icon cache. Low.
8. Fixed: ChatGPT sheet: when signed in, the first button still says "Continue with ChatGPT", and the
   email has no "Signed in as" label (`mac-chatgpt-before.jpg`).
9. Fixed: Devices sheet: each row's menu shows "••• Connection" (ellipsis plus text, large blue text on
   iPhone); a known device with no access in either direction shows no status; the device-name field
   has no label (`mac-devices-before.jpg`, `ios-devices-before.png`).
11. Fixed: expanded computer results dumped raw JSON; iPhone tool rows were tinted accent blue.
12. Fixed: at launch the pane was blank and the model picker showed no name, then the wrong model.
14. Fixed: single newlines in replies collapsed into spaces (CommonMark soft breaks).
15. Not changed: an old conversation still shows "The ChatGPT request failed or reached a usage
    limit…"; current code no longer produces that wording, so it is a saved status from before.
16. Fixed (client) / pending deploy (service): Stop erased the partial reply and showed nothing.
17. Fixed: "Thinking" stayed visible under streaming text.
18. Fixed: an open conversation on iPhone showed no title; device chip state relied on contrast.
19. Checked: iPhone composer grows and keeps Send reachable; a long simulated typing burst was
    truncated by the injection tool, not the app (short text appended normally). Mac memory was
    about 150 MB resident with current history; long-history memory remains an open TODO.
13. Background computer use cannot change the Mac sidebar selection (AX press doesn't select List
    rows) or open toolbar pop-up menus; the iPhone simulator covered those shared views.
10. Toolbar pop-up menus can't be driven in the background by computer use, so menu contents were
    checked on iPhone and in code. Menu-bar commands now cover the same actions on the Mac.
7. AppleScript `quit` addressed to `com.iamnoah.agent` reports the app is not running (shared
   bundle ID with the helper); menu quit works.
