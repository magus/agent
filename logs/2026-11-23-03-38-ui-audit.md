# UI audit and desktop control fixes

## Context

Overnight, open-ended audit of the native Mac and iPhone clients aimed at a useful, clean, simple
agent UI, with every change verified in the running apps (computer use on the Mac app, the
simulator tool on iPhone). Noah also decided that computer use must work whether the Mac is locked
or unlocked; the locked-only guard was a misunderstanding. Work happens on branch `ui-audit`;
nothing is pushed. Scratch: `.scratch/2026-11-23-03-38-ui-audit/`.

Constraints: no System Settings or permission changes, no ChatGPT sign-in changes, no pairing
changes, no deleted conversations. The Mac mini is read-only (info, harmless shell, capture); its
Agent app and the central service it hosts are not rebuilt or restarted.

## Plan

- P1 (desktop control), P2 (first audit pass), and P3 (top fixes) are done. Remaining time goes to
  finer passes; items that need a service deploy or Noah's decision are under Follow-ups.
- Second session (Nov 24): finer passes covered keyboard and focus (Mac menu commands, iPhone
  focus and keyboard dismissal), VoiceOver names, destructive confirmations, accessibility text
  sizes on every iPhone sheet, light mode, quarter-screen and full-screen Mac windows, search
  sources and images, code copy, idle CPU, dead UI paths, and copy. The ranked list under
  Findings → Open is current.

## Decisions

- Desktop control runs locked or unlocked. Each result reports the real `locked` state instead of
  a hard-coded `true`, so the model knows whether a person may be at the Mac. The setup preview no
  longer requires an unlocked Mac either.
- The model instructions live in `src/agent/service/chat/instructions.txt`, which the central
  service on the mini reads. They are updated in the repo but stay old on the mini until Noah
  deploys there.

## Follow-ups

Proposals that need Noah's call (not implemented):

- Rename and delete conversations: a sidebar context menu on the Mac and swipe actions on iPhone.
  Needs central-service endpoints; deleting is destructive, so the behavior (archive vs delete) is
  Noah's decision.
- Show remote devices' tool availability in the chat UI. The model already gets the reason; the UI
  only knows about the local Mac. The service could include cached per-target status in the
  conversation response.
- Long histories: every agent message is its own web view, measured at load. Caching measured
  heights (keyed by text, width, and font size) would avoid creating a web view per old message.
- iPhone landscape: the chips row, the pickers, and the composer (send button plus 14 + 16 pt
  padding) leave about two lines for the conversation (`iphone-landscape.png`). Letting the
  composer start at one line made no difference (its height comes from the button and padding),
  so that was reverted. A real fix means tightening composer padding and moving the pickers when
  height is compact, which is a design call.

- VoiceOver: nothing announces when a reply finishes or fails, so a VoiceOver user has to keep
  checking. Posting an accessibility announcement ("Reply finished", or the notice text) when
  `running` goes from true to false would fix it. Not done because the announcement can't be
  checked with the headless tools; it needs a VoiceOver check by hand.

- iPhone with a hardware keyboard: Return adds a newline and nothing sends, so the only way to
  send is tapping the button. ⌘Return on the send button (iOS only; the Mac composer sends on
  Return) would fix it. Not done because the simulator runs headless here, so a modified key press
  can't be sent to test it.
