# Review of chat, device, and desktop changes

## Context

Reviewed the 48 files changed from `87036d3` to `7c29020` on `ui-audit`, including the
service, native clients, renderer, and documentation. The request was for findings only.

## Decisions

- P2 findings affect normal behavior or make a failure hard to diagnose. P3 findings have a
  narrower trigger or impact. Each confirmed finding has a reproduction or a direct code path.

## Changes

**Confirmed findings, in severity order**

1. **P2. Startup and first-connection errors disappear.**
   `src/clients/apple/shared/chat/ChatView.swift:122` hides the composer until a service is selected.
   It also hides the only chat view that displays `model.error` (line 376). For example, malformed
   saved selection JSON makes initialization throw. The empty state suppresses its spinner on error
   (line 268), so the user gets a blank pane. If a discovered service goes offline before the first
   connection, the host stays empty. The connection sheet shows its own pairing error, while the
   connect button writes the failure to the hidden chat error. Both paths should show the reason.
2. **P2. Rendering a reply can change the code it contains.**
   `assets/markdown/lineBreaks.js:27` appends spaces to source before parsing. It protects
   top-level fences but misses indented code, fences inside quotes, and multiline inline code.
   The production renderer turned the two indented code lines `alpha` and `beta` into
   `"alpha  \nbeta\n"`. A multiline inline code span rendered with three spaces between its
   words instead of one. Copied examples can acquire different literal string contents.
3. **P2. A successful response can be recorded as interrupted.**
   `src/agent/service/chat/agent_loop.rs:637` infers interruption from the last visible row
   whenever the cleanup guard drops, including on success. A completed response with an empty
   output array reaches the Ready return at line 370. No row was added, so cleanup persists
   “Interrupted before replying.” The stream reader already has a test accepting exactly that
   completed payload. The saved transcript should distinguish an empty completion from a failure.
4. **P2. Idle chat polls start desktop helpers even before a service is chosen.**
   `src/agent/native_bridge/client_bridge.rs:96` asks for tool availability on every snapshot.
   A Mac execution device with an expired two-second cache synchronously spawns
   `desktop_service --permissions` and waits up to two seconds. The one-second idle poll
   continues even with an empty service host, when no device chip or banner can use the answer.
   This creates recurring process launches and can delay other requests on the same Swift Client
   actor. The dispatch-time permission check is independent of this display path.
5. **P3. Retrying an accepted message changes sidebar order.**
   `src/agent/service/central_service.rs:149` updates activity for every successful send.
   `AgentLoop::start` at line 129 also returns success for an existing receipt without appending a
   message. If A's acknowledgment is lost, a user sends to B, and A retries later, A moves above
   B even though B received the latest new message.
6. **P3. Two conversations active in the same second sort by ID.**
   `src/agent/service/service_store.rs:42` stably sorts records from an ID-ordered map.
   Line 229 discards fractions of a second. If conversations with IDs beginning with 1 and 9
   receive messages in that order during one second, 1 remains first. The newer conversation
   should lead. On connect, the client also selects the first record if none is selected.
7. **P3. CRLF replies gain extra paragraphs.** `assets/markdown/lineBreaks.js:10` splits
   only on LF. Given `one\r\ntwo`, the added spaces land between CR and LF. The renderer
   produced two paragraphs. The equivalent LF input produces one paragraph with a line break.
8. **P3. A helper that cannot launch never backs off.**
   `src/clients/apple/macos/DesktopService.swift:61` resets the delay based on the last
   successful launch. On a cold start with a missing helper, `process.run()` throws before
   setting `started_at`. Its value stays `.distantPast`, so every failure resets the delay
   to two seconds. The app repeatedly scans processes and logs the same failure instead of
   increasing the interval to the documented one-minute limit.
9. **P3. The audit log still asks for a completed deployment.**
   `logs/2026-11-23-03-38-ui-audit.md:610` asks for a mini deployment to enable recency,
   generated titles, and other service changes. Lines 409–417 of the same log record the
   deployment and successful live checks of those features. Following the open item would
   repeat a service restart. The later installer retry is separately identified as untested.

## Verification

- All 60 Rust tests passed with local socket access. The sandboxed run had denied socket
  creation in 19 tests. All five Markdown tests passed.
- Rendered indented code, a quoted fence, multiline inline code, and CRLF text using the
  installed renderer and inspected its HTML. The existing formatting test checks block counts
  and a top-level fence, which miss the changed text.
- Swift type checks passed for the macOS 15 client, iOS 18 simulator client, and desktop helper.
  Native UI behavior and live service installation were not exercised in this review.

## Follow-ups

**Unverified concerns**

- `assets/markdown/style.css:22` clips the code wrapper while the document view gives its
  preformatted child the full width of a long line. Verify that the rightmost character of a
  long JSON string is reachable by horizontal scrolling in the Pierre Words view on both
  platforms. The browser blocked the local HTML fixture, so this review did not establish
  the scrolling behavior.
- `src/clients/apple/shared/chat/ChatView.swift:37` observes changes to the Find counter after
  the view mounts. A Find command that creates the window may increment it before observation
  starts. The audit verified that a second Find focuses search. Close the chat window, press
  Find once, then type and check which field receives the text.
