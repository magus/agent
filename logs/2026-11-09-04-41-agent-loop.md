# Agent chat and tool loop

## Context

Phase two adds a small usable chat interface to the existing signed app, ChatGPT connection, and
paired-device tools. The model must not change device permissions.

## Decisions

- Keep device setup and account setup in their existing windows and menus.
- Save each tool request ID before submission. A lost connection must not repeat the action.
- Reuse subscription credentials. Select models from the account's returned catalog.
- Keep model execution separate from UI rendering and device authorization.

## Changes

- Added the initial GPUI chat window with model and target selection, a multiline prompt, tool history,
  screenshots, Send, Stop, and explicit result retrieval. Setup remains in separate menu windows.
- Added a Rust loop that reuses the ChatGPT client and a restricted tool connection wrapper.
  The wrapper exposes target information, submission, status, and cancellation, not pairing.
- Saved conversation inputs, outputs, tool IDs, and screenshot files under the private runtime folder.
  Interrupted tasks do not resume automatically. Recovery reads the original request ID.
- Stop prevents additional turns and submissions. It requests cancellation for submitted tools.
  An in-flight model HTTP request can finish in the background, but its response is discarded.
- Rendered model messages as Markdown and kept computer metadata behind a Details button.
- Shell requests now report failure for nonzero exits while preserving cancellation status.
- Validated tool arguments and authorized host IDs before saving a submission. Invalid calls return
  an error to the model without creating a pending remote request.
- Removed the duplicate Working message during device refresh after inspecting the scanning state.

## Verification

- All 26 tests passed outside the sandbox. The first sandboxed run failed because its loopback
  sockets were denied; it was rerun with the required network access. Clippy passed.
- The saved ChatGPT account returned the supported model catalog and a live text response.
- A model-requested shell command ran on the mini and returned its hostname and `703` for `37 * 19`.
- The model captured the locked mini, selected Calculator, entered `9 * 221`, and inspected the
  returned screenshot. Calculator displayed `1989`, and the model reported that observed result.
- Stop cancelled a running remote shell command. Retrieval returned `cancelled` with no final output.
- A model-requested `exit 7` returned that code without retrying the command.
- Restarted Agent during a remote shell command. The conversation reopened as interrupted.
  Retrieve results returned the original request ID and `reconnect-proof-8241`, without resubmission.
- Paused the mini's Agent process for 42 seconds to exceed the transport timeout. The loop stopped
  with an explicit connection error. After resuming the process, retrieval returned the same request
  and `device-interruption-9033`. No action was repeated.
- Changed the selected model from `gpt-6.1-sol` to the returned `gpt-6-luna` option. It read the
  recovered result from the saved conversation and answered without running tools.
- Stop before model work left no additional response or tool request. No pending request remained.
- The final installed build ran a model-requested local MacBook shell command, captured the locked
  mini, displayed the screenshot beside its action, and reported the visible `1989` result.
- Inspected the actual GPUI chat on both Macs, model choices, Markdown, restored history, screenshot
  display, Details controls, setup menus, and device refresh. The mini has no ChatGPT account saved;
  its chat shows that sign-in is required, while remote tools continue to work.
- All 26 tests, Clippy with warnings denied, formatting, and diff checks passed after review.
- Apple accepted notarization `17adad0e-fe38-44a2-9673-e776fc2dc016`. Both Macs run identical signed
  app and helper binaries with valid stapled tickets. Existing identities and grants survived.
- Final checks passed for a failed shell command and locked capture. MacBook-to-mini access works;
  mini-to-MacBook access is rejected.
